Catalogs are registries of installable extensions, presets, and bundles, which customize the Spec-Driven Development (SDD) lifecycle for your project. For each type of customization — extensions, presets, and bundles — there are two primary catalogs:

  • Default contains extensions, presets, and bundles maintained as part of Spec Kit.
  • Community contains extensions, presets, and bundles contributed by the broader community.

Extensions add new commands (what you run to drive a new lifecycle phase in your SDD process), templates (shape the phase's output), and scripts (the helpers that prepare each phase).

Presets customize commands, templates, and scripts to tailor how Spec Kit's lifecycle phases run.

Bundles package a curated set of extensions and presets into a single, versioned, role-oriented setup.

Spec Kit ships with a set of core command, template, and script files that define the Spec-Driven Development (SDD) lifecycle of your project. Three kinds of customizations can layer on top of core:

  • Presets customize core command, template, or script files. Each row below shows the winning version, plus the strategy used to combine it with core:
    • Replace — use the preset's version; ignore core.
    • Wrap — preset content surrounds core content.
    • Prepend — preset content is added before core.
    • Append — preset content is added after core.
  • Extensions add their own commands, templates, scripts, or hooks alongside core — they don't replace anything, they extend the lifecycle with new artifacts.
    • Hooks — attach to lifecycle events (e.g. after_specify) and run in addition to whatever else is registered.
